Reverse DNS and Blacklists: Why Your PTR Record Matters

Reverse DNS links your IP to a hostname. Learn why mail servers check it, how to set it correctly, and how a missing PTR record hurts delivery.

What reverse DNS is

Reverse DNS, or rDNS, is a PTR record that maps an IP address back to a hostname, the opposite of normal DNS, which maps a hostname to an IP. When a mail server receives a connection from your IP, it can look up the PTR record to see what hostname claims that address. A proper PTR record points to a real, forward-resolving hostname, such as mail.example.com, and that hostname resolves back to the same IP. This forward-confirmed reverse DNS is a basic identity check that most mail servers perform, and it is one of the first things a blacklist operator looks at when judging whether an address is a legitimate mail server.

Why mail servers care

Spammers often send mail from addresses with no PTR record, a generic PTR record assigned by an internet provider, or a PTR record that does not match the sending hostname. Legitimate mail servers, by contrast, almost always have a proper PTR record. Checking reverse DNS is therefore a cheap and effective way to filter out a large share of spam at connection time. Many servers will reject or heavily penalise mail from an IP with missing or generic reverse DNS, even if the IP is not blacklisted. Some blacklist operators also treat a missing PTR record as a listing criterion, so fixing it can help both delivery and delisting.

How to check your PTR record

You can check reverse DNS with our Reverse DNS Lookup tool, which queries the PTR record for any IP address over DNS-over-HTTPS. Enter your sending IP and read the hostname it returns. A good result is a hostname under your own domain that resolves back to the same IP. A generic result, such as a hostname owned by your hosting provider or internet provider, suggests the record was never customised. No result at all means no PTR record exists. Check every outbound IP you use, because a server with several IPs may have a correct record on one and a missing record on another.

How to set it correctly

PTR records are controlled by the owner of the IP address, which is usually your hosting provider or your internet provider, not your DNS host. To set one, log in to your hosting dashboard and look for a reverse DNS setting, or open a support ticket asking for a specific PTR record. Choose a hostname under a domain you control, make sure that hostname has an A record pointing to the same IP, and use a sensible mail hostname such as mail.example.com. Avoid hostnames that look dynamic or generic, and avoid pointing the PTR record at a hostname that resolves elsewhere. After the change, allow a few hours for DNS to propagate and then re-check.

PTR records and blacklist removal

When you request delisting, operators often check your PTR record as part of their review. A missing or generic record suggests the server is not a properly maintained mail server, which makes approval less likely. Setting a correct PTR record before you submit the request, alongside SPF, DKIM, and DMARC, shows that you run a legitimate operation. It will not remove a listing on its own, and it will not fix a spam problem, but it removes one of the commonest objections operators raise. Think of it as part of the basic hygiene that every mail server should have, alongside authentication and a clean sending history.

Frequently asked questions

Can I set a PTR record myself?

Only if you own the IP block. Usually your hosting or internet provider controls it, so you must ask them to set the record you want.

What hostname should I use for PTR?

A hostname under your own domain that resolves back to the same IP, such as mail.example.com. Avoid generic provider hostnames.

Will a PTR record alone fix delivery?

No. It is one check among many. You also need authentication, a good reputation, and clean sending practices.
